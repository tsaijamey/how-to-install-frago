## Overview

把一台未配置的机器变成可用的 frago 源码安装：安装前置依赖、克隆仓库并用 uv 建环境、手工完成等价于 `frago init` 与 server 自动配置的全部动作（config.json、runtime.json、hook 二进制部署、settings.json hooks 段合并），最后逐项验证 hook 链路。适用于不运行 frago server 的场景，以及需要第三方 Anthropic 兼容端点的环境。

## Steps

### 1. 安装前置依赖（按 OS）

- 通用：git、uv；浏览器自动化需要 Google Chrome（可选装）。
- macOS：`xcode-select --install` 提供 git；uv 用 `curl -LsSf https://astral.sh/uv/install.sh | sh`。
- Linux（apt/dnf/pacman）：安装 git、curl；Chrome 从 dl.google.com 安装 deb/rpm。
- Windows：`winget install Git.Git`；uv 用 `powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`。
- Python 不必预装：uv 会按 pyproject 的 `requires-python>=3.13` 自动下载托管 Python。

### 2. 克隆与建环境

- `git clone https://github.com/tsaijamey/frago.git` 到稳定路径（如 `~/frago`），在仓库目录执行 `uv sync`（普通使用不需要 `--all-extras --dev`）。
- 完成后 CLI 入口是 `<仓库>/.venv/bin/frago`（Windows 为 `<仓库>/.venv/Scripts/frago.exe`）。包名 frago-cli，entry point `frago = frago.cli.main:cli`。
- hook 二进制随仓库分发：`src/frago/bin/<平台>/frago-hook` 已 git tracked，平台目录为 darwin-arm64 / darwin-x86_64 / linux-x86_64 / windows-x86_64（Windows 文件名 frago-hook.exe）。不支持的平台（如 linux-aarch64）hook 功能不可用，但 CLI 仍可用。

### 3. 生写配置（替代 init 与 server 自动配置机制）

正常流程中 frago server 启动时会部署 hook 二进制、按二进制 `--supported-events` 输出注册 hooks、写 runtime.json；脱离 server 时手工完成等价动作：

1. `~/.frago/config.json`（不存在才写，已存在绝不覆盖）：`{"schema_version": "1.0", "auth_method": "official", "init_completed": true}`。auth_method=official 表示不干预用户现有 Claude Code 认证。
2. `~/.frago/runtime.json`：`{"schema_version": "1.0", "launcher": {"command": ["<仓库绝对路径>/.venv/bin/frago"], "mode": "global", "detected_at": "<ISO时间戳>", "source": {}}}`。这是 Rust hook 调起 `frago book` 的唯一依据，缺失或 launcher 为空时 hook 静默不工作（设计好的失败模式）。Windows 路径必须用正斜杠（如 C:/Users/...），因为 Claude Code 在 Windows 经 Git Bash 启动 hook，反斜杠会被当转义吃掉。
3. 部署 hook 二进制：`mkdir -p ~/.claude/hooks/frago/`，把 `<仓库>/src/frago/bin/<平台>/frago-hook` 拷过去，POSIX 上 `chmod 755`。
4. `~/.claude/settings.json` hooks 段合并写入，绝不整体覆盖用户已有 settings：先运行 `<二进制> --supported-events`（输出 JSON 数组）动态获取事件清单（当前为 SessionStart、UserPromptSubmit、PreToolUse），对每个事件追加 `{"matcher": "", "hooks": [{"type": "command", "command": "<~/.claude/hooks/frago/frago-hook 的绝对路径>", "timeout": 10}]}`；若已有同 command 的注册则跳过。
5. 确认无需生写的文件：hook-rules.json（builtin 规则编译在 Rust 二进制内，用户文件只是覆盖层）、`~/.frago/books/`（系统知识在 Python 包内，用户域目录懒创建）、AGENTS.md 与 `~/.frago/.gitignore`（写入代码已随旧 sync 栈删除）。`~/.frago` 其余子目录（recipes/、projects/ 等）由 CLI 懒创建。

### 4. 可选：第三方 Anthropic 兼容端点

仅当没有 Anthropic 官方认证、要用兼容端点（deepseek/aliyun/kimi/minimax/custom）时：向 `~/.claude/settings.json` 的 env 段合并写 ANTHROPIC_BASE_URL、ANTHROPIC_MODEL、ANTHROPIC_DEFAULT_SONNET_MODEL、ANTHROPIC_DEFAULT_HAIKU_MODEL、API_TIMEOUT_MS、CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC、ANTHROPIC_API_KEY 七键；并确保 `~/.claude.json` 含 `{"hasCompletedOnboarding": true, "lastOnboardingVersion": "1.0.0", "isQualifiedForDataSharing": false}` 三字段以跳过官方登录引导。预置端点示例：deepseek base_url=https://api.deepseek.com/anthropic。

### 5. 验证

1. `<仓库>/.venv/bin/frago --version` 输出版本号。
2. `<仓库>/.venv/bin/frago book` 输出知识索引。
3. `~/.claude/hooks/frago/frago-hook --supported-events` 输出三事件 JSON。
4. 重启 Claude Code 新会话，SessionStart 注入知识索引，说明 hook 链路 runtime.json → frago book 全通。

任何一步失败的排查指向：runtime.json launcher 路径是否绝对且存在、settings.json hooks 注册的 command 路径是否正确、二进制是否有执行权限。
